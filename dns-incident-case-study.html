DNS Troubleshooting & Incident Resolution

This case study demonstrates an end-to-end Level 1 IT Support incident, from identifying a user's connectivity problem to diagnosing the DNS misconfiguration, restoring access, documenting the fix and closing the support ticket.

Incident Overview

Incident type: DNS resolution failure

Affected workstation: WIN10-CLIENT2

End user: Sarah Johnson (sjohnson)

Technician workstation: IT-WS01 (Ubuntu)

Remote support tool: Remmina (RDP)

Ticketing system: GLPI

Root cause: Incorrect DNS server address configured as 192.0.2.1.

Correct DNS server: DC01 — 192.168.255.10

Outcome: DNS resolution and website access restored; resolution documented and ticket closed.

Resolution Summary

  1. Identified the user's DNS resolution failure.
  2. Connected remotely to WIN10-CLIENT2 using Remmina.
  3. Investigated connectivity and DNS lookup failures.
  4. Consulted the IT network reference document to confirm the correct DNS server.
  5. Replaced the incorrect DNS address with 192.168.255.10.
  6. Verified successful DNS resolution and website access.
  7. Documented the resolution and closed the GLPI ticket.
